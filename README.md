# 只見川 川霧 観測・予測プログラム（weather_visualizer.py）

**Google Colab で動かすことを前提にしたプログラムです。**

只見川流域の気象データ（気象庁ダウンロード形式の Excel / CSV）を読み込み、

1. **気温・湿度・風速・降水量などの気象データ**と、
2. **各地点の川霧・層雲・霧雨などの現象コード**

を月ごとにグラフ化し、さらに **RandomForest と XGBoost のハイブリッドモデルで地点ごとに霧の発生を学習**して、
**Open-Meteo API から取得した今後16日間の気象予報**をもとに、地点ごとの霧予測グラフとCSVまで自動生成します。

### `run()` に指定できるもの

```python
run(
    "/content/只見_気象データ.xlsx",   # 入力ファイル（.xlsx / .xlsm / .csv）
    "output_graphs",                  # 出力フォルダ（既定: ./output_graphs）
    sheet=None,          # Excelのシート名（省略時は先頭シート）
    layout="auto",       # 列の決め方（"auto"=見出しから自動検出 / "fixed"=従来の固定列）
    lat=37.3486,         # 予報を取得する地点の緯度（既定＝只見町付近）
    lon=139.3122,        # 　　　　〃　　　　　　経度
    forecast_days=16,    # 予報日数（Open-Meteoの上限は16）
    history_days=5,      # ④のグラフに表示する実測データの日数
    model="hybrid",      # 学習モデル（"hybrid"=RF+XGBoost / "rf"=RandomForest単独 / "xgb"=XGBoost単独）
    model_cache=None,    # 学習済みモデルの保存/再利用先（例: "models.joblib"）
    location_coords_file=None,  # 地点名,緯度,経度のCSV（地点ごとに予報を取得したい場合）
    forecast=True,       # False にすると霧予測（④⑤⑥）を作らない
    monthly=True,        # False にすると月別グラフ（①②）を作らない
    font=None,           # 使う日本語フォント名（例: "IPAexGothic"）
    show=None,           # セル内にグラフを表示するか（既定: ノートブックなら表示）
    zip_output=False,    # 出力フォルダをZIPにまとめる
    download=False,      # ZIPをそのままダウンロードする
    save_log=True,       # 実行ログをファイルにも保存する（出力フォルダに「実行ログ_日時.txt」）
)
```

## 入力データのフォーマット

気象庁からダウンロードした形式を想定しています。既定（`layout="auto"`）では、
見出し行の文字から次の列を自動的に探します。

| 探すもの | 見出しに含まれる文字 |
|---|---|
| 日時 | 年月日時 / 年月日 / 日時 / 日付 / 時刻 |
| 気温 | 気温 |
| 降水量 | 降水量 / 降水 |
| 風速 | 風速 |
| 風向 | 風向 |
| 露点温度 | 露点 |
| 相対湿度 | 相対湿度 / 湿度 |
| 観測地点（現象コード列） | 気象要素より右にあり、名前が付いている列 |

見出し行の**下に続く小見出し行**（気象庁形式の「風向」「品質情報」「均質番号」など）も見出しとして読みます。
`test.xlsx` のように風向が見出しの1行下に書かれている形式でも、風向を特徴量として使えます
（小見出し行はデータ行として読み込まれません）。

**観測地点ではない列は自動的に除外します。** 判定は次の2段階です。

1. **見出しで判定**：「品質情報」「均質番号」「現象なし情報」「水温」「水位」「流量」「視程」「日照」などの語を含む列、
   および `水温(℃)` `積算値(mm)` のように**単位が付いた見出し**の列。
   （`(川口橋)` のような括弧付きの地点名は単位ではないので地点のままです）
2. **中身で判定**：見出しでは分からない列でも、入っている値が `/` と 1〜10 の整数（`1 8` のような複数記入も可）で
   なければ地点とみなしません。**例えば水温 `8.2` は、整数部分だけ見ると「8＝濃い層雲」として学習されてしまいます。**
   これを防ぐため、値が現象コードらしくない列（1割を超えて不一致）は学習に使いません。
   まだ何も記入されていない列は、これから使う地点として残します。

除外した列は実行時に **「地点として扱わなかった列」** として理由付きで表示されるので、
意図しない列が混ざっていないかをその場で確認できます。

自動検出がうまくいかない場合は `layout="fixed"` を指定すると、従来どおりの固定列
（A=日時, B=気温, E=降水量, H=風速, S=露点温度, V=相対湿度, AC〜BH=現象コード32地点, 3行目=地点名）で読み込みます。

見つからなかった気象要素は欠測（NaN）として扱い、実行時に警告を表示します。
**降水量が見つからない／空欄の場合は 0mm として学習に使います**（無降水時に空欄という記録が多いため）。

### 日時の表記

次の表記に対応しています。

- `2024年6月28日1時`（気象庁形式）
- `2024年6月28日24時` → **翌日の0時**として扱います（気象庁は1時〜24時で1日を表すため）
- `2024/6/28 1:00`、`2024-06-28 01:00`、Excelの日付セル、Excelのシリアル値
- 年が省略された `6月28日1時` → 直前の行の年を引き継ぎます（12月→1月なら翌年）

日時として解釈できなかった行は除外し、その件数と例を実行時に表示します。

### 現象コードの意味

| コード | 意味 | 分類 |
|---|---|---|
| `/` | 現象なし | - |
| （空欄） | まだ観測結果が入力されていない | - |
| 1 | 薄い川霧 | 霧 |
| 2 | 川霧 | 霧 |
| 3 | 濃い川霧 | 霧 |
| 4 | 薄い全体霧 | 霧 |
| 5 | 全体霧 | 霧 |
| 6 | 全体濃い霧 | 霧 |
| 7 | 薄い層雲 | 雲 |
| 8 | 濃い層雲 | 雲 |
| 9 | 霧雨 | 雨 |
| 10 | 雨 | 雨 |

`/`（現象なし）と空欄（未入力）はExcel上は見た目が似ていますが、プログラム内部では区別しています
（`encode_phenomena_cell()` が空文字列は欠測、`/` は現象なし＝コード0として扱います）。
全角の `／` や `１０` も正しく解釈します。

## 出力されるファイル

すべて出力フォルダ（既定 `./output_graphs`）に保存されます。
ファイル名の先頭に付く `{接頭辞}` は、**入力ファイル名から自動で作られます**
（`_` または半角スペースがあればその手前まで。例: `test.xlsx` → `test_…`、`只見_気象データ.xlsx` → `只見_…`）。

### ①②：気象データ × 現象コード（月別・全地点まとめ）

- `{接頭辞}_①気温・湿度・露点×現象コード_YYYY-MM.png`
- `{接頭辞}_②風速・降水量×現象コード_YYYY-MM.png`

上段が気温・湿度・露点温度・風速・降水量の時系列、下段が全地点ぶんの現象コードを
色分けした帯（レーン）で表示します。横軸の日付は `年/月/日` 形式です。

- **その月に記録が1件も無い地点はレーンから外します**（記録の無い空白レーンを描いても読みにくいだけのため）。
- **1枚に16地点を超える場合は画像を分割**します（`_1of2`・`_2of2` のようにファイル名の末尾が付きます）。
  32地点あるファイルでは、①②とも1か月あたり2枚ずつになります。

### ④：地点ごとの16日間予測グラフ

- `{接頭辞}_④{観測地点名}_16日間予測_YYYYMMDD.png`

- **上段**：直近5日間の実測気温・露点・湿度（実線）＋ 今後16日間の予報（同色・点線）。
  凡例はグラフの外（上）にまとめて表示し、線に重ならないようにしています
- **中段**：**霧（コード1〜6）の予測確率**。多クラス分類の予測は多数派の「/」に寄りやすいため、
  「霧になりかけている時間帯」も読み取れるように確率を併記しています。
  目安の横線（霧警戒ライン）は固定50%ではなく、**地点ごとに検証期間で最適化したしきい値**です
  （凡例に実際の値が出ます。例:「霧警戒ライン（25%・地点ごとに最適化）」）
- **下段**：その地点の現象コード。実測・予測とも①②と同じ配色で表示し、
  予測ゾーンは背景のグレーと境界線（縦の点線）で示します
- 実測の最終記録と予報開始が2日以上離れている場合は、**横軸を「実測」と「予報」に分割**して描きます
  （空白をそのまま描くと図が極端に横長になり読めなくなるため。つなぎ目に `//` を表示します）

### ⑤：日別霧予測サマリー

- `{接頭辞}_⑤日別霧予測サマリー_YYYYMMDD.png`

- **上段**：日ごとに「霧（コード1〜6）が予測された地点数」を棒グラフに、
  「霧確率の平均（全地点・全時刻）」を折れ線で重ねて表示します
- **下段（新規）**：**地点×日のヒートマップ**。その日の霧確率の最大値を地点ごとに色の濃さで示し、
  どの地点がいつ危ないかを一覧できます。50%以上のマスには数値も表示します

### ⑥：予測結果CSV（2種類）

- `{接頭辞}_⑥予測結果_YYYYMMDD.csv` … **既定（縦持ち）**。列は「日時・地点・予測コード・現象名・霧確率(%)・判定」。
  地点数が多くてもExcelで右にスクロールする必要がなく、フィルタや並べ替えもしやすい形式です。
  「判定」列は、その地点の霧確率が**地点ごとに最適化したしきい値**を超えていれば「霧」、そうでなければ「-」になります。
- `{接頭辞}_⑥予測結果_横持ち_YYYYMMDD.csv` … 従来形式（地点ごとに列が並ぶ）。ピボット表を作りたい場合などに。

いずれもBOM付きUTF-8で、Excelでそのまま開けます。

## 霧予測の仕組み

1. **目的変数**：地点ごとに、その時刻の現象コード（0=`/`〜10）をそのまま多クラス分類のラベルとして使います
   （霧か否かの二値化はしていません＝元データと同じ粒度で予測します）。
2. **学習データ**：**実際に観測結果が入力されている行だけ**を使います（空欄＝未観測の行は自動的に除外）。
   さらに `find_dummy_blocks()` により、一定期間まとまって「/」がほぼ皆無なブロックを
   テスト用ダミーデータの疑いがあるものとして自動的に除外します。
3. **特徴量**：気温・降水量・風速・相対湿度・露点温度に加えて、
   - 気温と露点温度の差（気温露点差）
   - 時刻を sin/cos に変換したもの（0時と23時が近いことをモデルに教えるため）
   - 月
   - 風向の sin/cos（風向の列がある場合のみ。静穏は sin=cos=0）
   - **直近の変化量**：気温の1時間・3時間の変化量、直近3時間の風速平均、直近24時間の降水量合計
     （川霧は「その瞬間の値」よりも「直近の変化」に左右されやすいため。ちょうどN時間前の実測が
     無い行はNaNになるが、学習データが不必要に減らないよう妥当な既定値で埋めます）
   - **日の出まで残り時間**：放射冷却で気温が下がりきる明け方に霧が出やすいが、日の出時刻は季節で
     大きく変わるため、「月」「時刻」だけでは表現しきれない季節ごとの日の出の早い/遅いを補う特徴量です
     （NOAAの簡易式による近似。緯度経度は予報取得地点で代用）
   - **日照時間・気圧・日射量・視程**：ファイルにこれらの列があり、有効値が十分（既定5%以上）あれば
     自動的に特徴量として使います（無ければ何も起きません。見つかった場合は実行時の確認表示に
     「（任意・特徴量として使用）」と出ます）
4. **モデル**：**RandomForest と XGBoost のハイブリッド**を**地点それぞれに個別に学習**します。地点間でデータを混ぜることはしません。
   - 2つのモデルの**予測確率を加重平均**します（`確率 = w × RandomForest + (1 - w) × XGBoost`）。
     RandomForest は少数・不均衡なデータで安定し、XGBoost は細かいパターンを拾いやすいという性質の違いを両取りするためです
   - 混合比 `w` は **地点ごとに自動で決めます**（候補は 0 / 0.25 / 0.5 / 0.75 / 1.0）。
     `w=1.0` は RandomForest 単独、`w=0.0` は XGBoost 単独と同じなので、**片方が明らかに良い地点では自動的にその片方だけが使われます**
   - 評価用の train/test 分割は**時系列順を保ち**、後ろ20%をテストに使います（未来データが学習に混ざらないようにするため）。
     混合比と、霧確率のしきい値（下記）は**さらにその学習データの後ろ20%（検証期間）だけ**で選ぶので、テスト期間の成績が甘くなることはありません
   - `RandomizedSearchCV`（`TimeSeriesSplit`）で、RandomForest は `n_estimators`・`max_depth`・`min_samples_leaf`・`max_features` を、
     XGBoost は `n_estimators`・`max_depth`・`learning_rate`・`subsample`・`colsample_bytree`・`min_child_weight` を探索します。
     探索の目的関数は**霧F1**（コード1〜6のmacro F1。霧が無ければmacro F1で代替）で、以前のf1_macro（全クラス平等）から
     霧の当たり具合を直接最適化するように変更しました
   - 交差検証の分割数が足りない場合は探索をスキップし、既定値（RandomForest: `n_estimators=500, max_depth=14, min_samples_leaf=2` /
     XGBoost: `n_estimators=300, max_depth=4, learning_rate=0.1`）にフォールバックします
   - データ件数が少なすぎる地点（200件未満）や、現象の種類が1種類しかない地点は、下記の「共通モデル」で補います
   - 学習後、地点ごとに正解率・F1スコア・**霧F1**（コード1〜6に限定した macro F1）・**霧判定のしきい値**・**採用した混合比**を一覧表示します
     （評価期間に現象が1種類しかない地点は「※正解率は参考値」と表示します。「/」が大多数だと正解率は簡単に高くなるため、霧の当たり具合は霧F1で確認してください）
   - 表の最後に **`平均霧F1の内訳 → RandomForest単独: … / XGBoost単独: … / ハイブリッド: …`** を表示します。
     ハイブリッドにして本当に良くなったかを毎回その場で確認できます。続けて、**地点ごとに効いている特徴量トップ3**（重要度）も表示します
   - **xgboost は Google Colab に標準で入っている**ため、Colabでは追加の作業は不要です。
     入っていない環境では自動的に RandomForest 単独に切り替わります（その旨を表示します）。
     学習時間が気になるときは `--model rf`（`run(..., model="rf")`）で従来どおりの速さに戻せます
5. **霧判定のしきい値**：④のグラフの目安線・⑥CSVの「判定」列は、固定50%ではなく
   **地点ごとに検証期間でF1が最大になるしきい値**を使います（`_choose_fog_threshold()`）。
   検証期間に霧が無い（または常に霧）地点は、判定のしようがないため既定の50%のままです。
6. **共通モデル（プーリング）**：個別の学習条件を満たさない地点（データ不足・現象の種類が少ない）は、
   **全地点のデータを合わせて学習した共通モデル**で補います。只見川流域は同じ気象条件の影響を
   受けるという考え方です。共通モデルは地点を区別しないため、地点固有の霧の出やすさまでは学習
   できない点に注意してください（学習ログに「共通モデルで学習できた地点」として一覧表示されます）。
   共通モデル自体を学習するための最低件数（全地点合計500件）・地点ごとに評価するための最低件数
   （30件）は `MIN_TOTAL_ROWS_FOR_POOLING` / `MIN_ROWS_FOR_POOLED_RESCUE` で調整できます。
7. **予測**：Open-Meteo（無料・APIキー不要）から**実行した日（今日）以降**の気象予報を取得し、
   学習済みモデルで地点ごとの現象コードと霧確率を予測します。
   風速は `wind_speed_unit=ms` を指定して取得します（既定はkm/hで、指定しないと学習データ（m/s）と単位が食い違います）。
   日照時間・気圧・日射量・視程も同時に取得し、学習データ側でその項目を使っている場合に備えます。
8. **地点ごとの予報（任意）**：既定では全地点が1地点分（`--lat`/`--lon`、既定は只見町付近）の予報を
   共用しますが、`--location-coords 地点名,緯度,経度のCSV` を指定すると、そのCSVにある地点だけ
   Open-Meteoから個別に予報を取得します（1回のリクエストでまとめて取得するため通信回数は増えません）。
   CSVに無い地点は従来どおり既定の1地点分の予報にフォールバックします。

## 実行時に表示される確認情報

「Excelから読めているのか」「Open-Meteoから取れているのか」を毎回確認できるようにしています。

- 読み込んだファイルの**絶対パス・見出し行・どの列から何を読んだか・有効値の件数・期間**
- **検出した観測地点の一覧**（列 → 地点名）

- 日時として解釈できず除外した行の件数と実例
- Open-Meteoの**取得URL・緯度経度・件数・期間・先頭3行**
- 地点ごとの学習中・グラフ生成中は**進捗バー**（`[████░░░░] 12/32（38%） 経過18秒 地点名`）を表示し、
  処理が止まっているように見えないようにしています
- 既定では出力フォルダに **`実行ログ_YYYYMMDD_HHMMSS.txt`** として、画面に表示した内容をそのまま保存します
  （Colabのセル出力は再実行すると消えてしまうため。`--no-log` / `run(..., save_log=False)` で無効化できます）

## 既知の制限・注意点

- **Google Colab 前提**：ローカルのPCでも動きますが、日本語フォントの自動導入や
  ファイルのアップロード／ダウンロード支援はColabに合わせて作っています。
- **予報地点は既定1点**：`--location-coords` を指定しない限り、`lat` / `lon` で指定した1地点の予報を
  全地点の予測に使っています（既定値は只見町付近＝37.3486, 139.3122）。地点ごとの正確な座標が
  分かる場合は `--location-coords` で地点ごとの予報に切り替えられます。
- **「/」の記録がない地点**：現象があった時刻だけを記入している地点は「現象なし」の例を学習できないため、
  予測が現象側に偏ります（実行時に警告を表示します）。
- **季節性の偏り**：只見川の川霧は主に6〜9月の早朝・夕方に発生しやすいため、その季節を含まないデータ期間では
  霧サンプルがほぼゼロになり、学習できない地点が出てきます。
- **共通モデルは地点を区別しない**：データ不足の地点を補う共通モデル（上記「霧予測の仕組み」6.）は、
  全地点で同じ気象条件なら同じ予測を返します。地点固有の霧の出やすさの違いまでは反映しません。
- **霧確率の数値は未校正**：「霧確率89%」の89という数字は、RandomForest/XGBoostの生の出力であり、
  実際の発生頻度と正確に一致するとは限りません（確率校正は未実装。今後の改善の候補を参照）。
- **観測記録と予報のあいだの空白**：現象コードの入力が気象データ本体より遅れていることがあります。
  この空白そのものは埋められません（過去の実測値がないため）。3日以上空いている場合は警告を表示し、
  ④のグラフでは横軸を分割して表示します。
- **インターネット接続が必須**：予測グラフの生成にはOpen-Meteo APIへのアクセスが必要です。
